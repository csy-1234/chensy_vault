**适配屏幕宽度、像素密度与触控交互**，技术上依赖 **viewport、响应式布局、相对单位、高分屏图片、触控优化**。

==物理像素==
Physical Pixels
设备屏幕真正的点阵；硬件能显示的最小单CSS 并不会直接用它布局；
单位px；

==分辨率==
$$
分辨率=宽的物理像素*高上的物理像素
$$
例如iPhone 12 物理像素是 1170 × 2532 px（分辨率只是数量，不是屏幕大小）

==屏幕大小==
一般说手机屏幕 6 英寸，指的是 屏幕对角线长度 6 英寸（inch）

==像素密度==
Pixels Per Inch/PPI
每英寸像素数
1. 先算对角线像素数：
$$
对角线像素数= = \sqrt{W^2 + H^2}​
$$


2. PPI 公式：
    
$$
PPI= \frac{\text{对角线像素数}}{\text{屏幕对角线尺寸 D (inch)}}
$$

高 PPI → 同样尺寸下画显示能力更高清，显示更多细节；代表像素密度


==内容分辨率/内容像素==
图片 / 视频 / 资源本身的像素数量
- 手机屏幕 6 英寸，分辨率 4000 × 3000 px → PPI 很高
- 你放一张 800 × 600 px 的图片在全屏显示
    - 图片只有 800 × 600 px   
    - 高 PPI 屏幕把图片放大，物理像素拉伸 → 模糊
- ✅ 所以屏幕高清 ≠ 内容高清
单位px
内容分辨率与像素密度之间的关系

|屏幕 PPI|图片分辨率|显示效果|
|---|---|---|
|高 PPI|低分辨率|模糊（拉伸）|
|高 PPI|高分辨率|清晰|
|低 PPI|高分辨率|看起来细节少，但像素够，不拉伸|
|低 PPI|低分辨率|模糊|
高 PPI 能让高清内容更清晰，但不能自动让低分辨率内容变清晰

==CSS 像素 (CSS Pixels)/逻辑像素==
就是UI设计单位
浏览器用来做网页布局的单位；CSS 像素是虚拟的，用来统一网页布局的，而不是物理像素；实际写前端代码的px指的是css px（布局单位）；
单位px或rpx；
物理像素和逻辑像素的关系：
$$
物理像素=逻辑像素×DPR
$$

内容像素（图片的px）+逻辑像素（前端代码置顶的px），得到每个逻辑像素占映射的内容像素；
$$
每个逻辑像素占用的内容像素=\frac{内容像素}{逻辑像素}​
$$

每个逻辑像素占用1个及以上内容像素--清晰
不到一个，则模糊


情况1：内容像素 = 逻辑像素
    每个逻辑像素对应 1 个内容像素
    逻辑像素 → 物理像素映射由 DPR 决定    
    物理像素占用 = 逻辑像素 × DPR
举例：

	逻辑 200px，内容 200px，DPR=2  
	物理像素占用 = 200 × 2 = 400px  
	每个物理像素用 0.5 个内容像素 → 模糊

就是对比内容像素和逻辑像素\*dpr;
内容像素/物理像素<1,则模糊

情况2：内容像素小于逻辑像素
	每个逻辑小于一个内容像素
	显示系统必须 **拉伸内容像素** 来填满逻辑像素 → 模糊
	物理像素占用 = 逻辑像素 × DPR
	每个物理像素对应的内容像素 < 1 → 模糊明显
举例：

	逻辑 200px，内容 100px，DPR=2
	物理像素占用 = 200 × 2 = 400px
	每个物理像素对应内容像素 = 100 / 400 = 0.25 → 很模糊

情况3：内容像素 > 逻辑像素
	每个逻辑像素对应 **大于 1 个内容像素**
	系统可以缩小或等比例映射
	物理像素占用 = 逻辑像素 × DPR
	每个物理像素对应内容像素 ≥ 1 → 清晰
	这种情况，==多出来的物理像素，**插值** 或 **超采样** 技术来填充额外的物理像素==，并不是简单的拉伸原图，而是通过 **插值算法** 生成更多的像素数据，使得图像在显示时更 **平滑、细腻**。因此，图像的显示 **更清晰**，而不是失真或模糊
举例：

	逻辑 200px，内容 400px，DPR=2
	物理像素占用 = 200 × 2 = 400px  
	每个物理像素内容像素 = 400 / 400 = 1 → 刚好清晰


常见设备的DPR：
DPR 是 固定的设备属性，它决定了每个逻辑像素映射到多少物理像素
- **大多数普通设备**：DPR = 2（例如 iPhone 6、7、8）
- **高端设备**：DPR = 3（例如 iPhone X, 11, 12）
- **4K 屏幕、某些高端安卓设备**：DPR 可能是 4 或更高
- **低端设备**：DPR = 1（例如早期安卓设备）

DPR（设备像素比），主要是为了在 **小屏幕** 上实现 **高分辨率显示**，提高显示效果，让屏幕显示更清晰，减少“像素颗粒感”。这就是为什么移动设备的 **DPR** 通常会更高，尤其是高端智能手机。


高 PPI 和高 DPR 的关联
移动设备高ppi是因为：
	要放下同样高分辨的资源到移动UI，而不失真变形；
移动设备高ppi导致：
	如果不适用dpr，而是直接映射到物理像素，同样的内容会显得更小，像素间隔小/高PPI
因此
	为了保证显示效果不要完全依赖于物理像素，显示相同大小的效果，会依赖 DPR 来适配。
	**DPR > 1** 的设备/高分辨率的移动设备会有更多的物理像素来填充内容，这样就可以保证不会因为 PPI 较高而导致显示过小，附加效果是图像或文字的显示 更加清晰和细腻（使用插值与超采样技术填充额外的物理像素）

因此可以推理出：
	如果移动设备的像素密度是 PC 的两倍，那么 同一个设计的 `csspx` 在移动端和 PC 上会有不同的显示效果
	移动端设计 通常会考虑高 DPR（即高物理像素密度），所以开发时的 UI 设计会考虑 使用更多的逻辑像素 来适配高 PPI 屏幕
所以
	高 PPI 要对应高 DPR



图形变形

情况1：宽高同时压缩
当 **物理像素小于内容像素** 时，图像的显示通常会 **按比例压缩**，即同时压缩宽度和高度，保持宽高比不变。这样处理一般不会产生畸变，但会导致 **图像变小**，可能丢失一些细节。
这种压缩是 **等比例的**，因此不会产生畸变，但**可能导致图像的细节变差**，使得图像看起来不清晰，尤其是在较低分辨率设备上。

情况2：不等比例压缩或拉伸（单方向）
- **单方向的压缩或拉伸** 是造成 **畸变** 的主要原因之一。当屏幕或容器的 **宽度** 或 **高度** 比实际内容更大或更小时，设备可能会 **拉伸** 或 **压缩** 内容的 **单一方向**。
- **例子**：假设你的图片是正方形的 **100x100px**，但在设备上呈现时，设备可能将其强行拉伸为 **100x200px**。此时图像 **宽度被拉伸，而高度保持不变**，这就导致了 **纵向的畸变**，图像看起来会失去原有比例。
- **原因**：这种情况发生通常是因为 **容器尺寸** 或 **屏幕尺寸** 不符合原图的 **长宽比**，或者没有进行合适的适配。

情况3:平铺或拉伸过多

CSS 中的 `<img>` 标签的 **图片填充** 是 **等比例缩放**；



> [!Question] 问题
> 为什么直接用物理像素布局网页
> 设备差异太大（屏幕大小、分辨率）
> 直接用 **物理像素布局**，同一个网页在不同设备上会大小不一
> CSS 像素提供了 **统一的逻辑单位**，让布局和字体大小在各种设备上保持一致的视觉效果
> 高分屏上1csspx=多个物理像素（dpr>1）
> 



```
example
在 CSS 里你写的：
	width: 100px;
   height: 50px;
100px/50px 指的就是 CSS 像素，这是浏览器用来做布局的“逻辑像素”，和物理像素无关。
浏览器会根据设备的 DPR 把 CSS 像素映射到物理像素上去显示：
物理像素 = CSS 像素 × DPR
```

移动设备的两个屏幕宽度：
物理屏幕宽度：屏幕真正的像素点数，例如 iPhone 14：1170 px

CSS 宽度（viewport width）：iPhone 14 Safari 默认 375 CSS px
    
即 **浏览器布局使用 375px 宽度做参照**
        
- DPR = 物理像素 / CSS 像素 = 1170 / 375 = 3
    

✅ 所以你看到的网页布局宽度是 375px（CSS px），但是屏幕实际点阵有 1170 个像素（物理 px）

其他设备也有这些概念：
手机、平板、笔记本、pc台式都有：物理像素+默认css像素宽度+DPR
