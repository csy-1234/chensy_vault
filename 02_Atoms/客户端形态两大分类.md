C/S客户端形态


```
Client / Server（广义）
├── B/S（Browser / Server）
│   └── Web 项目
├── Native C/S
│   ├── 桌面程序
│   ├── 手机 App
│   └── 命令行工具
└── Hybrid C/S
    ├── App + HTTP API
    ├── Electron + Web
    └── 小程序
```

> **这两个 C/S 在“架构本质”上没有区别，  
> 区别只在「客户端技术形态 + 通信方式是否 Web 化」**

它们**不是两种架构**，而是 **同一架构（C/S）的两种实现风格**

Native C/S（传统 / 原生 C/S）
	客户端是**原生程序**
	协议通常是**私有协议或非 HTTP**
     客户端和服务端**强耦合**

特点

|维度|说明|
|---|---|
|客户端|C++ / Java / Swift / Kotlin|
|协议|TCP、私有二进制协议|
|更新|客户端必须升级|
|典型|QQ 早期、银行柜面系统|

👉 **这是“教科书里的 C/S”**

Hybrid C/S（现代混合 C/S）

定义

- 客户端仍然是**专用客户端**
    
- 但通信方式**完全 Web 化（HTTP / JSON）**
    
- 服务端像 Web 一样提供 API
    

 特点

|维度|说明|
|---|---|
|客户端|App / Electron / 小程序|
|协议|HTTP / HTTPS|
|服务端|REST / GraphQL|
|更新|服务端独立演进|

👉 **这是“现实世界里的 C/S”**
