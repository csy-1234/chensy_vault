**适配屏幕宽度、像素密度与触控交互**，技术上依赖 **viewport、响应式布局、相对单位、高分屏图片、触控优化**。

==物理像素==
Physical Pixels
设备屏幕真正的点阵；硬件能显示的最小单CSS 并不会直接用它布局；
单位px；

==分辨率==
$$
分辨率=宽的物理像素*高上的物理像素
$$
例如iPhone 12 物理像素是 1170 × 2532 px（分辨率只是数量，不是屏幕大小）

==屏幕大小==
一般说手机屏幕 6 英寸，指的是 屏幕对角线长度 6 英寸（inch）

==像素密度==
Pixels Per Inch/PPI
每英寸像素数
1. 先算对角线像素数：
$$
对角线像素数= = \sqrt{W^2 + H^2}​
$$


2. PPI 公式：
    
$$
PPI= \frac{\text{对角线像素数}}{\text{屏幕对角线尺寸 D (inch)}}
$$

高 PPI → 同样尺寸下画显示能力更高清，显示更多细节；代表像素密度


==内容分辨率/内容像素==
图片 / 视频 / 资源本身的像素数量
- 手机屏幕 6 英寸，分辨率 4000 × 3000 px → PPI 很高
- 你放一张 800 × 600 px 的图片在全屏显示
    - 图片只有 800 × 600 px   
    - 高 PPI 屏幕把图片放大，物理像素拉伸 → 模糊
- ✅ 所以屏幕高清 ≠ 内容高清
单位px
内容分辨率与像素密度之间的关系

|屏幕 PPI|图片分辨率|显示效果|
|---|---|---|
|高 PPI|低分辨率|模糊（拉伸）|
|高 PPI|高分辨率|清晰|
|低 PPI|高分辨率|看起来细节少，但像素够，不拉伸|
|低 PPI|低分辨率|模糊|
高 PPI 能让高清内容更清晰，但不能自动让低分辨率内容变清晰

==CSS 像素 (CSS Pixels)/逻辑像素==
浏览器用来做网页布局的单位；CSS 像素是虚拟的，用来统一网页布局的，而不是物理像素；实际写前端代码的px指的是css px（布局单位）；
单位px；
物理像素和逻辑像素的关系：
$$
物理像素=逻辑像素×DPR
$$

> [!Question] 问题
> 为什么直接用物理像素布局网页
> 设备差异太大（屏幕大小、分辨率）
> 直接用 **物理像素布局**，同一个网页在不同设备上会大小不一
> CSS 像素提供了 **统一的逻辑单位**，让布局和字体大小在各种设备上保持一致的视觉效果
> 高分屏上1csspx=多个物理像素（dpr>1）
> 



```
example
在 CSS 里你写的：
	width: 100px;
   height: 50px;
100px/50px 指的就是 CSS 像素，这是浏览器用来做布局的“逻辑像素”，和物理像素无关。
浏览器会根据设备的 DPR 把 CSS 像素映射到物理像素上去显示：
物理像素 = CSS 像素 × DPR
```

移动设备的两个屏幕宽度：
物理屏幕宽度：屏幕真正的像素点数，例如 iPhone 14：1170 px

CSS 宽度（viewport width）：iPhone 14 Safari 默认 375 CSS px
    
即 **浏览器布局使用 375px 宽度做参照**
        
- DPR = 物理像素 / CSS 像素 = 1170 / 375 = 3
    

✅ 所以你看到的网页布局宽度是 375px（CSS px），但是屏幕实际点阵有 1170 个像素（物理 px）

其他设备也有这些概念：
手机、平板、笔记本、pc台式都有：物理像素+默认css像素宽度+DPR
