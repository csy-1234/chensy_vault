> [!core]
> 系统 = 客户端形态 × 服务端架构 × 通信方式 × 节点角色组织方式


- **客户端形态**Client Form：用户“从哪里进来”
- **服务端架构**Architecture：系统“内部怎么组织”
- **通信方式**：两者“怎么说话”
- **节点角色组织方式**Topology：节点组织与角色分布架构    C/S、P2P
它们**彼此独立、可任意组合**。

第一轴：客户端形态（Client Form）
```
客户端形态
├── Browser（Web / B/S）
├── Native App（iOS / Android）
├── Desktop Client（PC 客户端）
├── Mini Program（小程序）
├── CLI / Script
└── IoT / Embedded
```

第二轴：服务端架构（Server Architecture）
```
服务端架构
├── 单体（Monolith）
├── 三层架构（Presentation / Business / Data）
├── SOA
├── 微服务（Microservices）
└── 事件驱动架构（EDA）
```

第三轴 ：通信方式（Communication）
```
通信方式
├── HTTP / HTTPS（REST / GraphQL）
├── RPC（gRPC / Thrift / Dubbo）
├── Message Queue（Kafka / RabbitMQ）
└── Stream / Event（WebSocket / SSE）
```

第四轴:   节点角色组织方式（Topology）
P2P 不是传统意义上的“服务端架构”，  
而是一种「节点组织与角色分布架构」,不是二层轴server architecture，而是“系统拓扑架构”


==二维正交组合图==
下面是**最核心的二维正交图**（不引入第三四轴，先保证清晰）：

|客户端形态 \ 服务端架构|单体|三层架构|SOA|微服务|EDA|
|---|---|---|---|---|---|
|**Browser（Web）**|Web 单体|Web 三层|Web + SOA|Web + 微服务|Web + 事件流|
|**App（iOS/Android）**|App + 单体|App + 三层|App + SOA|App + 微服务|App + 事件|
|**PC 客户端**|PC + 单体|PC + 三层|PC + SOA|PC + 微服务|PC + 事件|
|**小程序**|小程序 + 单体|小程序 + 三层|小程序 + SOA|小程序 + 微服务|小程序 + 事件|
|**CLI / IoT**|CLI + 单体|CLI + 三层|CLI + SOA|CLI + 微服务|CLI + 事件|

👉 **每一个格子，都是现实中真实存在的系统**
