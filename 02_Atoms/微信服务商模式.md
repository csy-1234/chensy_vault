微信支付体系中，除了“直连商户”（直接和微信签约）外，还有大量商户是通过**支付服务商**（比如随行付）接入微信支付的。这类模式叫**间连模式**（或服务商模式）。

整体流程顺序：
	1.使用手机号 + 验证码/密码注册随行付账户，获得一个随行付平台的登录账号，这是你后续所有操作的入口
	2.登录随行付平台，进入的是随行付的 SaaS 商户后台，不是微信官网
	3.提交子商户进件资料，随行付将这些资料代你提交给微信支付审核
	4..通过微信审核后，获得子商户号（sub_mch_id）子商户号 = 你的“身份证号“，随行付平台自动展示该号码，正式成为微信支付的子商户，但不能登录 pay.weixin.qq.com
	5.完成服务商授权，随行付平台提供授权二维码 → 用进件时填写的法人实名微信扫码授权，授权后，随行付才能调用微信接口为你收款、退款等
	6.使用子商户功能：在随行付平台的【交易管理】、【微信支付】等模块就是子商户后台”，由随行付封装微信 API 实现
	
>子商户号由微信生成，但不能登录微信官方后台;微信只为直连商户开放 pay.weixin.qq.com 后台，因为子商户号不属于直接与微信签约的（直连商户），两者是不同类型，微信不提供登录 pay.weixin.qq.com，用来登录直连商户的后台；


>子商户后台可以看到：
>交易查询、退款操作、结算明细、对账单下载、商户信息、通知配置、风控状态；子商户在随行付后台下载的对账单，是随行付加工后的版本，可能缺少某些字段。
>直连商户后台（pay.weixin.qq.com）后台类似




可以授权的接口：
收款类支付、查询类、退款类、对帐类、配置类
使用接口：
提供子商户id、服务商id、服务商api证书签名
服务商调用这些接口，需要传入子商户号（sub_mch_id）+ 自己的服务商号（mch_id），并使用自己的 API 证书签名。


授权完成流程；
1. **你（张三）** 向随行付提交资料：营业执照、身份证、银行卡；
2. **随行付** 将资料上传微信，申请子商户号；
3. **微信审核通过**，生成子商户号 `190XXXXX02`，并绑定“张三”为负责人；
4. **随行付** 给你一个授权二维码；
5. **你用张三本人实名的微信** 扫码，页面显示：“是否授权随行付管理商户 190XXXXX02？”；
6. 你点“同意” → 微信记录：**张三授权随行付操作其子商户**；
7. 此后，随行付就能合法调用微信接口，为你收款、退款、查账；
8. 你在**随行付后台**用手机号登录，就能看到所有数据。

**服务商不能随便生成子商户号，必须先提交你的真实身份信息；**  
**而你授权时，微信会用“你微信的实名信息”去匹配进件时的法人信息，这就是你的身份凭证；**  
**子商户号是你在微信系统的“身份证号”，但操作权限来自“法人微信授权”这一动作**





解释

 子商户号是微信官方生成，你们这个商户现在是随行付渠道的，随行付是微信的支付服务商
	
	你是随行付的子商户，不是直接和微信签约，而是通过随行付“间接”使用微信支付

授权是商户授权给随行付

	微信或随行付提供的页面上，授权随行付代表你操作微信支付相关功能

实际打款账户是随行付进件时的结算卡，微信支付只负责将交易资金结算到随行付的账户。随行付收到资金后，再进行清分，最终打到在随行付进件时绑定的结算卡上。


1. 顾客用微信付款 → 钱先**到微信支付平台**。
2. 微信按规则（通常是T+1）把这笔钱**结算给随行付的对公账户**（因为你是通过随行付接入的，微信只认随行付）。
3. 随行付收到所有子商户（包括你）的资金后，会做**清分**（即拆分每笔属于谁的钱）。
4. 然后随行付再把属于你的那部分钱，**打到你在随行付那里登记的结算银行卡**上。
⚠️ 注意：**微信不会直接打钱给你**！它只打给随行付，再由随行付转给你。
✅ 简单说：  
顾客付的钱 → 微信 → 随行付（汇总）→ 随行付分账 → 你的银行卡。


>**微信支付时，实际收款的“商户主体”是谁？**
>子商户号（sub_mch_id） —— 交易归属它
>也就是说：支付时：交易归属子商户--》支付接口传递子商户sub_mch_id,顾客支付看到的是进件时提交的商户简称（如“张三小吃店”）
>
>结算时：资金先到服务商账户
>服务商号（mch_id，即随行付）的对公账户
>
>**最终钱到谁的银行卡？**
>清分：服务商做二次分账
>- 微信不支持向子商户直接打款（因为子商户没有独立签约）；
>子商户在随行付进件时绑定的结算卡
>1. 按 `sub_mch_id` 汇总每个子商户的应结金额；
>2. 扣除自己的服务费（如有）；
>3. 通过**代付通道**（如银联、网联、合作银行）将钱打到：
> **你在进件时绑定的结算银行卡**（必须是法人或对公账户）
>- 这个过程叫 **“清分”** 或 **“分账”**（注意：不是微信官方的“分账产品”，而是服务商内部的资金划拨）；
>- 到账时间可能比微信结算日晚 1 天（T+2），取决于随行付的处理效率。
>顾客 → 微信 → 随行付汇总户 → 清分 → 子商户结算卡

接入微信收发货交易闭环流程
- 小程序必须与子商户号（或直连商户号）在微信系统中完成“绑定备案”，否则无法发起支付；这个绑定是向微信官方申报的，不是代码里随便写写就行的。代码只是“请求”，微信会校验“权限”，
- 涉及实物商品的小程序/公众号/H5 支付场景，
- 必须在用户付款后 **上传物流信息**（快递公司 + 运单号）或 **标记虚拟发货**；
- 否则会 **限制支付功能**（提示：“未接入发货管理，支付暂不可用”）。
> 📌 该能力通过微信的 **【订单发货管理 API】** 实现，属于 **“交易组件”** 的一部分。



**如果不接入微信的交易闭环（即未按要求上传发货信息），微信会直接冻结该笔交易的资金，不会结算给服务商（随行付）；  
这是微信平台层面的资金冻结，不是服务商内部的清算冻结。**
