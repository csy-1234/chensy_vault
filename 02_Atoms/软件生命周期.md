软件生命周期（SDLC, Software Development Life Cycle）是一个从软件需求分析到软件最终报废的全过程

1. **需求分析阶段**
	目的
		确定软件的需求、功能和性能要求
	执行操作
		与客户和用户沟通，收集需求；编写需求文档，明确功能需求、非功能需求（如性能、可用性、安全等）；进行需求评审和确认，确保没有遗漏
	产物
		《需求规格说明书》（SRS）
2. **系统设计阶段**
	目的
		根据需求分析阶段的结果，设计软件架构和详细设计
	执行操作
		高级设计：定义系统架构、模块划分、数据流和接口；详细设计：定义每个模块的功能、数据库设计、UI设计等；进行设计评审，确保设计符合需求，并考虑到可扩展性、性能等因素。
	产出
		《系统设计文档》（SDD）
3. **开发阶段**
	目的
		按照设计文档进行编码，完成软件开发。
	执行操作
		开发人员根据设计文档编写代码。
		持续集成（CI）：将开发的代码进行频繁合并，进行自动化构建。
		进行单元测试，保证各个模块功能正确。
		与团队成员进行代码评审，确保代码质量。
4. **测试阶段**
	目的
		验证软件功能和性能，确保软件符合需求并且无重大缺陷
	执行操作
		编写测试计划，确定测试类型（单元测试、集成测试、系统测试、验收测试等）。
		执行功能测试、性能测试、安全测试等。
	    提交缺陷报告，并进行缺陷修复。
		验证缺陷修复后软件的稳定性。
5. **部署阶段**
	目的
		将软件部署到生产环境，提供给用户使用。
	执行操作
		根据部署计划，将软件安装到生产环境中。
		配置服务器和数据库等生产环境资源。
		进行最后的验收测试，确保软件在生产环境中正常运行。
		培训用户，提供用户手册和技术支持。
6. **运维阶段**
	目的
		软件投入使用后，确保其正常运行并提供支持。
	执行操作
		监控软件的性能、稳定性，及时发现并解决问题。
		根据用户反馈，进行软件的维护和优化。
		修复生产环境中的漏洞和缺陷。
		执行备份和恢复操作，确保数据安全。
7. **更新阶段**	
	目的
		根据需求变化或技术升级，进行软件的更新和升级。
	执行操作
		收集新的需求或技术更新需求。
		修改、优化已有功能，增加新的功能。
		更新版本，进行回归测试，确保更新没有引入新的问题。
8. **报废/退役阶段**
	目的
		当软件不再满足业务需求或过时时，进行退役或报废。
	执行操作
		停止软件的维护和支持。
		安排数据迁移或备份，确保数据安全。
		删除过时的软件系统，进行环境清理。
		向用户说明软件的退役和替代方案。

> [!NOTE]
> 构建:把源码变成可用于部署的产物（生产部署物）的过程
> 核心环节通常有三步：**下载依赖→  编译→ 打包**

1️⃣ **下载依赖**（Dependency Resolution / Fetching）
编译之前，但有些构建工具在编译时自动处理依赖,依赖先行是最常见做法。

- 从仓库（远程或本地）获取源码或第三方库所需要的依赖文件。
- 确保源码编译时所有引用的库都可用
- 比如java下载jar包，nodejs项目下载npm包

2️⃣ **编译（Compilation / Build）**
下载依赖后，把源码转化成机器或运行环境可以识别的中间产物

- **语法检查**：确保源码没有语法错误
- **类型检查**：例如 Java 的类型检查、C++ 的类型匹配
- **编译生成目标文件**：
    - Java → `.class` 文件
    - C/C++ → `.o` 或 `.exe` 文件
    - TypeScript → JavaScript
- 对前端项目：JS/TS 代码通常要经过 **转译（Babel、TypeScript）** 或 **打包工具处理（Webpack/Vite）**

3️⃣ **打包（Packaging）**
编译成功后，将编译产物、依赖和资源文件整合成最终可部署产物。

- **整合依赖**：把之前下载的依赖和编译好的目标文件放在一起
- **加入资源**：配置文件、图片、脚本、静态文件等
- **生成最终部署产物**：
    - Java → Jar/War 包
    - Node.js 前端 → 压缩后的静态文件 + 依赖
    - Docker → Docker 镜像
- 有些构建工具还会生成 **版本号、构建信息、环境配置**
